## 数据流与功能

原文件分片上传到对象存储 → 校验并提交不可变 Raw → 后台逐 Episode 自动质检 → 对齐数值数据和视频帧引用 → 提交 Arrow/Lance、媒体索引 → 自动建立标注任务 → 视频/曲线/机器人姿态可视化 → 标注、修订、审核、发布、导出。

G1 LeRobot 的视频质检仍需解码：单线程、按相机顺序逐帧读取灰度数据，用于亮度、重复帧、损坏帧判断；不会保存 JPEG 或重新编码 H.264。对齐保留原 MP4 的对象引用和片段起止时间。媒体失败回滚与派生索引删除不拥有原始视频，不能顺带删除 Raw。

只有索引和必要数值派生物会新增存储。原视频仍按原编码由浏览器播放；浏览器支持的编码和硬件解码能力影响播放负载。历史已生成的 H.264 与原有标注继续读取，没有强制重算历史 154 个 Episode。

保留带平台清单的 MCAP 完整处理，以及原有切片、质检、对齐、标注、问题数据、审核、发布、导出和治理接口。MCAP 中图像消息生成可播放视频的编码仍有用途，不能与 LeRobot 原 MP4 的重复编码混为一谈。离线格式转换工具仍有明确调用和独立用途，没有仅凭文件名删除。

当前格式边界：通用 LeRobot、无平台清单的 MCAP、ROS bag 可以原样存档；任意机器人/自定义消息的自动处理仍需要对应适配器。现有原生处理适配器面向 G1 LeRobot v3，不能宣称所有 ROS bag 已支持完整可视化。

## 六个常驻容器

| 容器 | 职责 |
| --- | --- |
| `hc-data-platform-single-web-1` | 前端静态资源、API 与对象存储同源代理 |
| `hc-data-platform-single-api-1` | 上传、权限、查询、标注等业务 API |
| `hc-data-platform-single-worker-1` | 一个进程消费主任务与媒体任务两条队列，执行质检、对齐、媒体索引及维护任务 |
| `hc-data-platform-single-temporal-1` | 持久工作流、失败重试和任务状态 |
| `hc-data-platform-single-postgres-1` | 业务数据库及 Temporal 的两个数据库 |
| `hc-data-platform-single-minio-1` | 原始文件、必要派生物与模型资产 |

API 和 worker 共用一个后端镜像。两条队列保留原名称，避免已入队任务失去消费者。健康检查现在覆盖两条队列。删除已完成的 migration/minio-init 临时容器；部署时它们仍会一次性执行。删除被替代的 `hc-data-platform-api:storage`、`hc-data-platform-frontend:storage` 镜像。未删除数据卷。

主任务并发 1、媒体任务并发 1、FFmpeg 单线程；原视频缓存上限 5 GiB，可回收。Temporal 数据库连接池由默认每服务 20/10 缩为 4/2、空闲 2/1；实际避免了共享 PostgreSQL 的 80 个连接被占满而导致标注 API 500。此前配置遗漏的任务分发项目范围也已补齐。
