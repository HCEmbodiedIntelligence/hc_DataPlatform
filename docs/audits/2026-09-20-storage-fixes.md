# 原始存储、播放与部署修复记录

日期：2026-09-20。基于前一份 [全平台审查](2026-09-20-platform-audit.md)，本次围绕
“低资源存储原始 MCAP / LeRobot / ROS bag”落地。未把历史训练导出、标注和加工引擎整体重写。

## 已上线的默认行为

- 网页统一走原始分片上传，默认 `STORE_ONLY`，保留文件内容、目录及 SHA-256。
  同一数据集可接收多份目录；任务、机器人和 G1 标注配置不再是存储前提。
- MCAP、ROS1 bag、ROS2 SQLite/MCAP bag 目录接入原文件存储；LeRobot v3 相机按 features 识别，
  不再限制 G1 四相机模板。文件列表分页，支持直接下载。
- 原样提交只写 Raw 注册与已完成的存储记录；不写 episode 处理计划、不发 Temporal outbox，
  不生成 JPEG、H.264、对齐 Arrow、Lance 或标注任务。
- LeRobot 预览按范围读取 episode 元数据，返回原 MP4 与片段时间偏移。
  数值 Parquet、原视频不经过服务器全文件下载或解码。
- 四路共用主视频实际时间，主视频缓冲时公共时钟停止推进。普通播放使用温和速度校正；
  大幅漂移修正有冷却时间，跳转时明确同步。重复 canplay 不再反复强制 seek。
- 数值窗口失败有退避，关节显示降到 10 Hz，时间查找使用二分；避免逐帧 React 状态更新。
- 同步鉴权/维护许可 I/O 移出 ASGI 事件循环；代理临时写入放到线程中执行。
- 可选旧处理链路的 LeRobot 读取下推 episode 过滤，抽帧线程有上限；本地源缓存增加
  容量/TTL、LRU 与活跃文件锁。原文件预览本身不使用此缓存。

## 部署与删除

当前入口：<http://127.0.0.1:8088>。四个常驻容器：静态 Web、API、PostgreSQL、MinIO，
全部健康。API 的 `HC_PROCESSING_ENABLED=false`，镜像没有 FFmpeg，ready 不再依赖 Temporal。
CPU、内存、进程数、临时目录和日志均配置上限，见 [部署与迁移说明](../single-server-storage.md)。

复用原有数据库与 MinIO 卷，没有重新初始化账号或替换原始数据。应用了追加数据库迁移 013/014。
迁移前保存 36 MiB 的 PostgreSQL 自定义格式备份，并通过 `pg_restore --list` 检查可读取；
这不是异机恢复演练。私有环境文件和备份均不进入 Git。

已删除的无调用前端代码：旧上传预检页面分支、`UploadPrecheckPanel`、
`FolderBatchPreflightPanel`、`ManifestPreflightPanel`、`LeRobotConfiguration`、
`lerobot-targets` 及其无调用查询。此前删除的空 preview 模块和无调用 processor 包装器继续保持删除。
保留历史版本仍引用的媒体、Lance 与旧处理协议，未批量删除派生对象或历史迁移文件。

容器清理结果：

- 删除 20 个已停止的旧容器；[原挂载关系](2026-09-20-retired-containers.json) 已记录。
- 删除 42 个旧项目镜像标签，保留新存储镜像及一个备份维护镜像；
  [镜像清单](2026-09-20-retired-images.json) 已记录。
- Docker builder 清理报告为 33.71 GB；构建缓存统计从清理前 41.54 GB 降到 9.691 GB。
  Docker 镜像与构建缓存共享层，不能把两者差值相加当作实际回收空间。
- 删除测试数据库容器及已完成的一次性初始化容器，最终只剩 4 个运行容器。
- 未执行 volume prune；128 个现有卷仍保留，只有主数据库与 MinIO 两个卷参与当前运行。
  旧匿名卷可能包含其他数据库，不能仅因未挂载就判定可删除。

启动初期四服务约 430 MiB；实际视频测试后的观测合计约 547 MiB，其中 MinIO 有文件缓存。
这些是本机瞬时观测，既不是负载峰值，也不是新服务器容量承诺。

## 仍保留的边界

- ROS bag / MCAP 在此入口提供存档和下载，尚未新增任意消息类型的可视化。
- 原视频仍需浏览器解码；原编码不受支持时应下载原文件或显式进行兼容处理，本次不自动转码。
- 完整加工部署中的大数据集训练导出、命名字典/视频引用的 LeRobot 导出适配，
  以及鉴权统一续租和数据库连接池仍是独立改进项。它们没有被宣称为本次全部解决。
  当前轻量部署不启动后台加工/导出 Worker，默认原样上传不经过这些链路。
- 源视频与历史派生数据都在原卷中；后续清理历史派生对象需要先核对数据库和 Lance 引用。
- 暂未进行目标服务器的完整恢复和压力测试；迁移时应按部署文档验证实际数据与域名。
