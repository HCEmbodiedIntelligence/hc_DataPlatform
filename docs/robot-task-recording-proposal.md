# 机器人一键连接平台与选任务录制方案 待审核

**状态：待审核。更新日期：2026 年 10 月 19 日。审核通过后再编写本轮连接与选任务代码。**

目标是把日常采集操作收敛为：**平台创建任务 → 机器人选择任务 → 开始录制 → 停止后自动上传。首次接入时，机器人只需粘贴平台生成的连接链接，点击一次“连接”。**

平台地址、机器人身份和上传凭据由连接流程处理。操作员按任务名称选择采集任务，系统记录数据归属。换任务、连续录制和重启机器人，都不需要重新绑定平台。

平台入口以正在调整的[机器人接入流程调整方案](robot-ingest-onboarding-proposal.md)为准：**数据源页面 → 机器人接入标签页 → 对应机器人的接入详情**。“机器人接入”是数据源页内的标签页，平台页面结构由该方案统一定义。

主方案包含从设备接入到录制上传的完整流程。本文件补充机器人端交互、接口、异常处理和验收细节，两份文档采用相同的连接与任务规则。新设备使用数据源页内的“接入机器人”入口，已有设备使用“查看接入详情”；配置采集端统一使用一个连接链接。

后续机器人端代码统一在 `HC-teleop-robotic` 的 `main` 分支实现。此前 `humanoid` 工作区的录制快照、封存和上传队列作为实现参考，按本方案需要接入 `main`。

## 首次连接只需粘贴一个链接

### 用户操作

| 位置 | 用户操作 | 页面反馈 |
| --- | --- | --- |
| 平台 | 在“数据源 → 机器人接入”打开已有机器人的“接入详情”，点击“复制连接链接” | 复制用于连接的链接；新设备从同一标签页的“接入机器人”完成登记后直接复制 |
| 机器人 | 粘贴链接，点击“连接” | 显示连接进度 |
| 机器人 | 连接完成后直接选择任务 | 显示平台名称、机器人名称和可用任务 |

接入流程复用已有上传身份；尚未开通的新设备在同一流程内完成权限设置和身份创建，用户不用再去另一个入口创建身份、签发 Token。被主动停用的设备需要先恢复权限。

机器人未连接时的页面：

```text
连接平台

[ 粘贴从平台复制的连接链接                         ]

[ 连接 ]

在平台“数据源 → 机器人接入 → 接入详情”复制连接链接到这里。
```

连接成功后，同一位置变为：

```text
平台：采集平台     机器人：OpenArm 01     已连接

采集任务  [ 搜索或选择任务                         ]  [ 刷新 ]
```

主页面不要求填写平台地址、平台机器人 ID、本地机器人 ID、任务 ID、Token 或凭据文件路径。已有配置完整的机器人在自动验证成功后直接显示已连接状态；凭据修复和更换平台放在连接设置中。

### 点击连接后系统完成的工作

机器人从链接读取平台入口，自动读取当前机器人配置，并使用链接中的一次性票据向平台完成接入。平台确认票据对应的组织、机器人和上传权限，建立必要的本地采集标识映射，返回机器人身份与上传凭据。机器人保存连接配置后获取任务列表。

本地采集标识来自实际使用的机器人配置，不能通过改写录制文件冒充另一台设备。已有模型或采集映射与当前配置冲突时，页面给出具体问题并指向机器人配置；不能把“已连接”作为绕过格式与模型校验的依据。

**连接链接与任务无关。** 一台机器人连接一次后，可以选择多个符合权限要求的任务。同组织内切换项目下的任务也无需重新连接。

### 连接链接的约定

链接携带平台入口和短期一次性票据，自建平台和局域网部署均可使用，不依赖额外的公共配对服务。建议有效期为 **10 分钟**，过期后在平台重新生成。页面显示剩余有效时间。

链接由有权管理该机器人的平台用户生成，限定目标组织、机器人和已有上传权限。它不直接包含长期上传 Token；成功兑换后失效。同一次连接请求遇到超时可安全重试，不能重复生成身份或凭据。查看详情和生成链接不轮换凭据，普通连接不自动撤销其他有效凭据；管理员主动执行“更换上传凭据”时单独说明撤销范围，受影响的采集端通过新连接链接更新。

长期凭据由机器人服务保存到受限的本地凭据文件。浏览器仅显示连接结果，录制包和日志不包含凭据。连接请求失败时保留原连接；已有录制或上传作业仍按原连接处理。

新设备生成链接后仍待验证，机器人完成实际认证后显示连接结果。已有设备生成链接时保留其实际连接状态，不能因此重置为待验证或直接改为在线。

## 平台建好任务后机器人直接选择

### 机器人获取哪些任务

本稿建议首版展示：**机器人所属组织内，状态为进行中且满足该机器人上传条件的采集任务**。任务是否可选由平台判定；项目、数据集和 Region 由任务确定，机器人操作员无需重复选择这些归属信息。

当前任务模型没有“指派给某台机器人”的配置。为满足“创建任务后即可选择”，首版沿用同组织的有效任务范围，不增加必填的机器人分配步骤。如果业务需要只显示指定机器人的任务，可将“任务指派”加入本次范围；指派必须同时约束任务查询和上传接口。该选择列在文末审核项中。

任务列表支持按名称、任务编号搜索和按项目筛选。打开录制页面时自动刷新，页面可见时每 30 秒刷新一次，并提供“刷新”按钮。搜索和分页针对平台完整结果集。

| 列表内容 | 用途 |
| --- | --- |
| 任务名称 | 主要选择依据 |
| 所属项目和任务编号 | 区分同名任务 |
| 任务说明 | 告诉采集人员本次要录什么 |
| 可用状态及原因 | 解释任务关闭、格式不兼容或平台配置未就绪等情况 |

任务创建成功且接收条件已满足后，刷新即可看到。已关闭、已取消或已删除的任务不能作为新录制的目标；已选任务失效时明确提示，保留原选择用于识别问题，不自动换成列表第一项。

任务列表显示任务的最小必要信息，不能把人类用户的项目管理权限授予机器人凭据。跨组织任务不可见、不可选、不可上传。

### 录制页面

```text
平台：采集平台     机器人：OpenArm 01     已连接

采集任务  [ 杯子抓取 / 桌面操作项目 / 任务编号   ▾ ]  [ 刷新 ]
任务说明：从桌面抓起杯子，放到指定区域。

停止后自动上传：开启

[ 开始录制 ]
```

首次使用时由操作员明确选择任务。此后记住最近一次选择；再次进入页面时验证任务仍然可用，名称始终展示在开始按钮上方。任务选择不会改动机器人运动、话题、相机或采集格式设置。

点击“开始录制”时，机器人服务验证所选任务与当前连接，并把任务信息写入本次录制作业。验证失败会说明原因，操作员可以修复后重试，或明确选择“仅本地录制”。已经选择平台任务的请求不能悄悄退化为无任务录制。

录制过程中显示“正在录制：杯子抓取”，锁定本段任务。停止后可选择另一个任务开始下一段，前一段在后台继续整理和上传。

## 停止录制后自动完成上传

新连接默认开启“停止后自动上传”，连接成功时显示这一设置。用户也可以关闭自动上传，之后在录制列表中点击“上传”；上传仍使用这段录制开始时确定的任务。

```mermaid
flowchart LR
    A[平台创建任务] --> B[机器人选择任务]
    B --> C[开始录制并保存任务归属]
    C --> D[停止录制]
    D --> E[后台整理并上传]
    E --> F[平台处理与质检]
```

日常操作不再要求输入产物 ID、录制 ID，或手动执行“绑定并封存”“加入队列”。这些步骤由后台完成。录制列表直接提供查看、上传和重试操作。

页面分别显示“整理中、等待上传、上传中、已上传、平台处理中、处理完成”等进度，并单独显示质检结果。网络错误允许自动重试；配置或任务归属错误显示具体处理入口。上传成功不等于平台处理完成或质检通过。

### 每段数据的任务归属固定

| 操作 | 数据归属 |
| --- | --- |
| 选择任务 A，开始录制第一段 | 第一段记录任务 A |
| 停止第一段，选择任务 B 录第二段 | 第一段仍上传到 A，第二段上传到 B |
| 第一段上传失败后重试 | 仍使用第一段保存的任务 A |
| 修改默认任务、刷新页面或重启服务 | 已开始录制和已入队的数据保持原归属 |
| 更换平台连接 | 新录制使用新连接，旧作业保留旧平台和旧机器人归属 |

任务 ID 用于系统关联，任务名称和编号用于界面展示。选择任务与开始录制通过同一个启动请求提交，后端在启动临界区验证并保存，避免多个浏览器窗口通过修改全局默认绑定造成串任务。

## 断网和已有数据如何处理

| 情况 | 建议行为 |
| --- | --- |
| 正在录制时断网 | 当前录制继续，原任务归属保留；完成后的数据留在本地等待恢复上传 |
| 断网后要开始新的一段 | 首版支持明确选择“仅本地录制”；缓存的任务列表用于查看，不作为新的授权结果 |
| 网络恢复 | 有归属的队列继续按原任务上传；无归属数据提示“选择任务后上传” |
| 凭据过期、被撤销或机器人被停用 | 保留本地数据和队列，显示“连接需要处理”；已停用设备须先在平台恢复相应权限 |
| 任务在录制后关闭 | 已创建的上传沿用服务端会话规则；新建上传若被拒绝，保留数据并提示处理，不自动换任务 |
| 历史录制没有任务 | 在该条录制上选择任务后上传，不跟随当前页面默认任务自动归属 |
| 历史录制已经封存或上传 | 保持已有身份和归属；需要纠正归属时走单独的修正流程 |
| 平台更改了任务的数据集归属 | 上传前核对录制时保存的归属摘要；有变化时暂停并明确提示，避免无声进入另一个数据集 |

旧配置迁移时保留原平台、机器人、凭据引用和自动上传开关。把原绑定中的任务作为最近使用任务，经验证后展示；不因升级自动打开上传，也不重写已有录制包或队列。

仅本地录制后补选任务属于历史数据处理，普通联网采集仍然只需在开始前选任务。断网期间使用缓存任务开始新的平台录制可以后续扩展，需要接受任务已关闭等情况下上传被拒绝的结果。

## 实现范围和接口建议

本节用于审核开发范围，接口名称为拟议名称。平台继续复用已有上传协议与质检能力；机器人端以 `main` 为开发基线，接入本方案所需的录制收尾、上传队列和续传能力。

### 平台端

| 能力 | 拟议改动 |
| --- | --- |
| 生成连接链接 | 在“数据源 → 机器人接入”的接入详情和新设备接入流程中提供复制操作；有权管理该机器人的用户签发限定组织、机器人、有效期和权限的短期票据 |
| 兑换连接票据 | 新增一次性兑换接口；接收本地配置摘要和连接请求 ID，完成配置校验、凭据签发和幂等恢复 |
| 查询当前机器人 | 提供机器凭据可调用的身份接口，返回机器人名称、组织和可用上传格式等最小信息 |
| 查询可用任务 | 提供机器凭据可调用的搜索、分页和任务详情接口，并返回可选状态及原因 |
| 启动前校验 | 校验目标任务、身份、上传格式及当前可检查的接收条件；实际文件内容仍在上传处理时验证 |
| 上传归属校验 | 新建上传时复核任务状态和录制时的归属摘要，实际项目、数据集和 Region 仍由平台解析 |

建议新增机器侧接口包括 `POST /api/v1/robot-ingest/connections:redeem`、`GET /api/v1/robot-ingest/me`、`GET /api/v1/robot-ingest/tasks` 和任务详情或预检接口。签发连接链接使用平台用户权限，票据兑换只接受受限的一次性票据，后续任务查询使用机器人凭据。

### 机器人端

| 能力 | 拟议改动 |
| --- | --- |
| 平台连接 | 新增单输入框连接入口；机器人服务解析链接、兑换票据、保存凭据并读取任务 |
| 配置拆分 | 将长期的平台连接与当前选择的任务分开保存；旧 `binding` 继续供已冻结作业使用 |
| 任务选择 | 在开始录制旁提供任务选择器和刷新入口，浏览器通过本地服务获取任务 |
| 录制启动 | 明确提交本次连接、任务和录制模式；保存平台、机器人、任务及归属摘要，录制元数据不保存秘密 |
| 自动上传 | 完成收尾和必要封存后，按本段任务自动入队；手动上传与重试也使用同一份归属 |
| 历史录制 | 从录制列表选择条目补选任务，替代手填各种 ID |

所有能开始录制的入口，包括页面按钮和已有快捷操作，都需使用同一套任务选择规则。存在自动分段的采集会话时，应在会话开始时固定任务，各片段继承；修改任务在会话结束后生效。

首版同时交付单链接连接、任务列表、录制选择和自动上传，不把“一键连接”留到后续版本。现有运动控制、相机参数、采集格式和质检规则保持各自职责。机器人任务指派是否进入首版，由下一节的审核项决定。

## 审核时需要确定的产品选择

编号与主方案的审核表一致，任务固定规则对应 C，机器人连接和采集选择对应 G 至 J。

| 编号 | 建议采用的行为 | 审核关注点 |
| --- | --- | --- |
| C | 开始录制时固定任务，连续录制记住上次有效选择 | 切换任务只影响后续录制 |
| G | 机器人只粘贴一次连接链接并点“连接”，建议链接 10 分钟有效 | 日常界面不出现平台地址、各类 ID、Token 和凭据路径的配置表单 |
| H | 首版可选同组织内符合条件的进行中任务 | 如果只允许指定机器人执行，需要同时增加任务指派配置和服务端约束 |
| I | 新连接默认停止后自动上传 | 旧连接保留原开关，用户能在页面关闭 |
| J | 断网时允许仅本地录制，恢复后对无归属数据补选任务 | 首版不依靠缓存授权开始新的平台任务录制 |

## 验收标准

1. 首次连接时，机器人端只有一个链接输入框；粘贴并点击连接后自动显示正确的机器人和任务列表。
2. 链接过期、重复兑换和连接响应丢失均有明确结果；重试不重复创建身份或凭据，旧连接不会因失败被覆盖。
3. 平台创建有效任务后，机器人手动刷新即可看到，页面自动刷新也能更新；操作员无需复制任务 ID。
4. 同名任务能通过项目和任务编号区分；无权限、跨组织、已关闭任务不能通过手工请求绕过限制。
5. 选任务 A 录第一段，选任务 B 录第二段，即使第一段仍在处理或重试，两段也分别归属 A、B。
6. 停止录制后自动完成整理、封存和入队，界面显示上传、处理和质检各自状态。
7. 重启后恢复平台连接、最近选择和上传队列；恢复过程不改写已有数据归属。
8. 录制中断网不打断本地采集；恢复后按原归属续传。任务关闭或归属变化时明确提示并保留数据。
9. 历史未绑定数据可以从录制列表补选任务，已绑定数据不会被当前默认任务覆盖。
10. 现有完整配置可直接迁移，保留自动上传开关；多个浏览器窗口和各录制入口不会造成串任务。
