# 向已有项目的开发环境合并数据

此工具适用于 `compose.dev.yaml`，包括离线部署包的 `run.sh`。目标机器已有账号、项目或数据时，使用合并导入；整库恢复仍用于恢复到空环境。

入口是 `deploy/scripts/merge-dev-data.py`。它使用现有 API 镜像与绑定挂载的源码，不需要安装新的 Python 依赖或重新构建镜像，也不需要手工导出 SQL、修改主键或执行 `pg_restore` 覆盖业务库。两边须先同步本次新增的三个 `backend/src/hc_data_platform/backup/merge_*.py` 文件和包装脚本。

## 自动处理规则

| 情况 | 处理方式 |
| --- | --- |
| 目标已有项目 | 保留原项目，添加来源项目、数据集、标注和处理记录 |
| 相同组织 ID、项目 ID | 使用目标已有项目，保留目标项目名称 |
| 相同账号 ID 和用户名，例如 `hc_admin` | 保留目标的完整账号状态，包括密码、禁用状态和平台权限 |
| 用户名相同、账号 ID 不同 | 来源用户名自动增加稳定的 `_import_…` 后缀，历史作者 ID 保持不变 |
| 主键和整条记录相同 | 自动去重 |
| 审计记录自增编号冲突 | 为来源日志分配目标的新编号 |
| 两边都有审计完整性链 | 保留目标原链，把来源事件追加到链上并验证；来源原链保存在迁移包中 |
| 文件 key 相同且内容一致 | 校验 SHA-256 后复用目标文件 |
| 重复导入同一个迁移包 | 返回已导入结果，不重复插入或重新覆盖记录 |

同一业务主键对应不同业务内容、同一个账号 ID 对应不同身份、同一个文件 key 对应不同字节时，工具返回明确冲突并回滚数据库。这些情况无法通过主键重编号保证历史关系仍然正确，因此不采用“最后写入覆盖”或静默跳过。

## 1. 本机导出

在当前电脑的项目根目录执行：

```bash
cd /home/czy/hc_DataPlatform
python3 deploy/scripts/merge-dev-data.py export --bundle artifacts/data-transfer-20260922
```

工具记录服务的运行状态，暂停 API、Worker 和网页入口，检查 Temporal 没有运行中的流程且没有待发送 Outbox 事件，导出一致的数据库记录和 MinIO 文件，再恢复原先运行的服务。导出期间本机网页暂时不可用；数据库、MinIO 和 Temporal 继续运行。

包中包含账号密码哈希、业务配置和数据文件，目录权限为 `0700`、文件权限为 `0600`，通过 SSH 传输，不提交 Git。文件及表记录都有校验值；未完成的导出没有有效清单，不能导入。

## 2. 传到远程

在当前电脑执行，`rsync` 可以继续传输中断的文件：

```bash
rsync -a --partial --append-verify --info=progress2 \
  -e 'ssh -o ServerAliveInterval=15 -o ServerAliveCountMax=6' \
  /home/czy/hc_DataPlatform/artifacts/data-transfer-20260922/ \
  hc_op@192.168.31.126:workspace/data-transfer-20260922/
```

迁移包包含对象文件原始字节，体积可能接近原有 MinIO 数据量；它与此前约 1.1 GB 的镜像部署包用途不同。

如果持续出现 `Broken pipe`，可用自动重试脚本。默认限速 8 MiB/s，连接错误后等待 5 秒再试，最多 20 轮；磁盘写入、权限等其他错误会停止。限速用于降低传输负载，不能保证修复底层网络问题。

```bash
bash deploy/scripts/transfer-merge-bundle.sh \
  artifacts/data-transfer-20260922 \
  hc_op@192.168.31.126 workspace/data-transfer-20260922
```

日志保存在 `artifacts/transfer-logs/`。SSH 重连仍可能要求输入密码，密码不保存在日志中。可以通过 `HC_TRANSFER_KIB_PER_SECOND` 调整限速（`0` 表示不限速），通过 `HC_TRANSFER_MAX_ATTEMPTS` 调整尝试次数。

每轮 rsync 的百分比独立计数，从较小百分比开始不代表已传数据被删除。已完成文件会跳过，较短文件会续传并校验；保持原迁移包及远程目录不变。可在远程另一个终端观察累计文件大小：

```bash
watch -n 2 'du -sh ~/workspace/data-transfer-20260922'
```

目录大小只显示累计落盘量，不代替内容校验；远程 `import` 会校验完整清单和每个文件的 SHA-256。仅在传输命令成功结束后执行导入。

## 3. 在远程预检和导入

远程离线部署包根目录中执行：

```bash
cd ~/workspace/hc-data-platform-offline-71eaa560
sg docker -c 'python3 app/deploy/scripts/merge-dev-data.py plan --bundle ../data-transfer-20260922'
```

`plan` 会校验全部迁移包文件、数据库版本和约束、账号冲突、目标文件内容，并用真实数据库回滚事务演练合并；数据库记录和序列均不提交，目标文件也不写入。它也会暂停应用服务，以获得稳定的检查结果。暂停时长取决于数据量和磁盘速度。

预检通过后执行：

```bash
sg docker -c 'python3 app/deploy/scripts/merge-dev-data.py import --bundle ../data-transfer-20260922'
```

导入命令自身也包含预检，不强制要求先手工执行 `plan`。它自动导出并验证目标数据库备份 `target-before.dump`，完成文件传输、数据库事务合并与完整性验证后，再恢复原先运行的服务。结果保存在 `artifacts/data-merge/<运行时间>/report.json`，备份位于同一目录。

浏览器重新登录后，原有项目和导入项目都应可见。查看数据集数量，并打开一个已有标注、视频和原始文件进行检查。迁移不携带来源登录会话；目标管理员仍使用目标原密码。

## 失败、重试与边界

- 数据库插入、约束验证、审计链更新、序列调整和导入回执在同一个事务内。提交前失败会回滚；原有目标记录保持不变。
- 对象只允许在 key 不存在时写入，已有文件从不覆盖。网络中断后，少量已经复制但尚未被数据库引用的新文件会保留，以便重新执行同一导入命令时校验并复用。
- 导入事务提交后发生输出报告失败，可再次执行同一命令，通过数据库回执确定之前已经完成的导入。
- 只恢复执行前正在运行的应用服务；原本停止的服务保持停止。包装脚本异常时也会尝试恢复服务，并保留备份、迁移包和错误输出。
- 本版面向相同数据库结构、相同 bucket 名称、相同数据源凭据加密密钥的本地 Compose 环境。结构或密钥不一致会在写入前停止。
- 支持未启用版本管理的 MinIO/S3 bucket。版本管理或暂停版本管理的 bucket、未完成的分片上传、单对象超过 5 GiB 会明确拒绝；总数据量不受 5 GiB 限制。当前部署使用未启用版本管理的 MinIO。
- 不合并运行中的 Temporal 工作流或其内部数据库；活动任务须先完成。已落库的处理历史保留，历史记录中遗留的 `RUNNING` 字样不会被伪造为处理成功。
- 来源会话、验证挑战、限流状态、媒体处理容量锁、部署配置、发布控制、备份目录等环境状态不进入目标运行环境，原记录仍保存在迁移包内。目标使用自身部署配置、入口 IP 和运行状态。
- 工具不是在线双向同步或生产环境灾难恢复。导出后来源继续发生的修改不会自动进入已经生成的迁移包。
