# HC Data Platform 主设计系统

> 状态：效果图阶段共享基线；不是最终生产样式合同
>
> 页面覆盖：认证状态、P01–P20、统一数据可视化工作台
>
> 规则：设计具体页面前，先读取本文件；若 `pages/<page-name>.md` 存在，则仅在明确记录的范围内覆盖本文件。未经 T01/主协调终端同意，不得修改本文件。

## 1. 设计对象

- 产品：部署在公网的工业机器人数据采集、质检、转换、标注、清洗、审核与发布平台。
- 用户：公司内部运营、研发、审核与发布人员；后续还包括被项目授权的采集、标注和清洗外包人员。
- 主要平台：桌面 Web；平板承接列表与审批；手机只承接认证、待办、状态和轻量审批。
- 页面首要任务：让用户迅速判断“数据现在处于哪一阶段、为什么停住、我下一步能做什么”，同时保持真实数据血缘和权限边界可追溯。

## 2. 视觉方向：机器人遥测账本

设计不是通用 BI 仪表盘，也不是机器人营销网站。它应像一个可信的“机器人遥测账本”：清楚、精密、可审计，但不把内部 ID、原始纳秒和协议细节直接倾倒给业务用户。

### 2.1 记忆点：信号轨道

唯一重点视觉元素是“信号轨道”：一条由采集、接收、自动质检、30 Hz 对齐、Lance、标注、清洗、审核和发布节点组成的细线轨道。

信号轨道只在以下位置出现：

- P01 主链路摘要。
- P03/P04 单个数据包的处理时间线。
- P06/P07 采集条目和版本的血缘摘要。
- P20 任务进度中的 Saved / Received / QC 差异。

轨道编码真实顺序和状态，不作为装饰。异常节点使用图标、文字和形状共同表达，不能只靠颜色。

其他区域保持安静，避免大量渐变、发光卡片、漂浮装饰或每张卡片都使用强动效。

## 3. 对自动候选方案的自我审查

`ui-ux-pro-max` 的首次自动候选为金色/奶油色、Roboto、营销落地页和滚动揭示。该候选只保留“高密度、低动效、状态色、可访问性”的原则，其余不采用，原因如下：

- 金色/奶油色会把工业数据工作台变成通用暖色模板，并与当前紫蓝主题产生无必要的全面推翻。
- 标题与正文全部使用 Roboto 缺少中文适配和层级差异，也会增加公网字体加载依赖。
- “Hero + 试用 CTA + 信任标识”属于营销落地页结构，不适用于登录后的操作平台。
- GSAP 滚动揭示对高密度操作台没有业务价值，且增加依赖和注意力干扰。

修订后保留当前视觉资产中有效的紫蓝基调、系统中文字体、Ant Design 组件基础和 Lucide 图标体系，并用信号轨道形成与机器人数据业务相关的独特识别。

## 4. 设计参数

- 差异度：4/10。结构稳定，独特性集中在信号轨道和数据血缘表达。
- 动效：2/10。仅用于状态变化、抽屉/弹层和可视化光标联动。
- 密度：8/10。适合桌面操作台，但必须通过分组、渐进展开和层级保证可扫读。
- 圆角：中等；沿用现有 10/12/18/24 px 层级，不做全站直角化或过度胶囊化。
- 阴影：只表达层级，不用彩色光晕。
- 主题：本阶段先完成浅色模式；颜色全部使用语义 Token，为未来深色模式预留，不在本轮扩展实现范围。

## 5. 色彩系统

### 5.1 核心色

| 语义 | 建议值 | 当前映射 | 使用方式 |
|---|---:|---|---|
| Primary / 主动作 | `#5965D8` | `--hc-color-primary` | 主按钮、当前导航、选中轨道节点 |
| Primary hover | `#4C57C6` | `--hc-color-primary-hover` | 悬停与强调 |
| Focus | `#8B96FF` | `--hc-color-focus` | 2–4 px 可见键盘焦点环 |
| Signal / 数据信号 | `#3B82C4` | 新语义 Token，效果图先使用 | 正常数据流、折线、时间轴光标 |
| Accent / 轻强调 | `#82D2FF` | `--hc-color-accent` | 选区、辅助高亮，不用于大面积 CTA |
| Page | `#F0F2F8` | `--hc-color-page` | 页面背景 |
| Surface | `#FFFFFF` | `--hc-color-surface` | 卡片、表格、工作区 |
| Surface muted | `#F6F7FB` | `--hc-color-surface-muted` | 次级分区、只读区域 |
| Text | `#171A2A` | `--hc-color-text` | 主文本 |
| Text muted | `#676B80` | `--hc-color-text-muted` | 次级信息；必须验证对比度 |
| Border | `#D9DDEA` | `--hc-color-border` | 结构边界 |

### 5.2 状态色

| 状态 | 建议值 | 规则 |
|---|---:|---|
| 成功/通过 | `#2F7D66` | 必须同时显示“通过”等文字或图标 |
| 等待/风险 | `#A86512` | 用于等待、RISK、即将超时 |
| 失败/拒绝 | `#B84646` | 用于失败、REJECT、危险动作 |
| 信息/处理中 | `#356EE8` | 用于处理中、同步中和链接 |
| 中性/未开始 | `#7A7F93` | 用于未开始、停用、不可用 |

禁止：

- 不用红绿作为唯一差异。
- 不把业务异常全部画成高饱和红色大块。
- 不在组件内写散落 Hex；效果确认后统一映射语义 Token。
- 不使用金色/奶油色自动候选作为新主品牌色。

## 6. 字体与数字

| 角色 | 字体栈 | 用途 |
|---|---|---|
| 标题 | `Segoe UI Variable Display`, `PingFang SC`, `Microsoft YaHei`, sans-serif | 页面标题、关键阶段名称；权重 600–680 |
| 正文 | `Segoe UI Variable`, `PingFang SC`, `Microsoft YaHei`, `Noto Sans CJK SC`, sans-serif | 表格、表单、帮助文字 |
| 技术值 | `Cascadia Mono`, `SFMono-Regular`, Consolas, monospace | 按需展开的 ID、哈希、Topic、时间戳 |

规则：

- 不新增阻塞渲染的公网字体依赖。
- 默认正文 14 px 适用于桌面高密度工作台；移动表单输入至少 16 px。
- 页面标题、区块标题、正文、标签、说明采用稳定字号阶梯，不用极大营销标题。
- 数字列使用等宽数字；日期、时间、容量和数量使用 `Intl` 本地化格式。
- 默认展示业务格式，完整纳秒、字节、哈希和内部 ID 放在技术详情中。

## 7. 布局系统

### 7.1 桌面框架

```text
┌──────────────┬──────────────────────────────────────────────────────┐
│ 功能导航     │ 项目上下文 / 全局搜索 / 通知 / 账户                 │
│              ├──────────────────────────────────────────────────────┤
│ 采集与接收   │ 页面标题 + 状态摘要 + 唯一主动作                   │
│ 数据生产     ├──────────────────────────────────────────────────────┤
│ 治理与资产   │ 筛选 / 视图 / 批量动作                              │
│ 安全与审计   ├──────────────────────────────────────────────────────┤
│              │ 主内容：列表、详情或统一工作台                      │
└──────────────┴──────────────────────────────────────────────────────┘
```

- 1440×900 为主效果图。
- 1280 宽度必须完成核心任务，不能出现整页横向滚动。
- 表格可在自身容器内横向滚动，固定主标识列和主动作列。
- 页面最多一个主 CTA；次要和批量动作降级显示。
- 筛选超过常用 3–5 项时进入“更多筛选”。
- URL 必须可表达项目、筛选、分页、Tab 和选中对象等可分享状态。

### 7.2 统一工作台

```text
┌─────────────┬────────────────────────────────────┬─────────────────┐
│ 任务/对象列 │ 多相机 / 机器人状态 / 数据可视区域 │ 标注/清洗/审核 │
│ 可折叠      │                                    │ 工具面板        │
├─────────────┴────────────────────────────────────┴─────────────────┤
│ 信号轨道 + 时间轴 + 播放控制 + 异常/评论标记                       │
└────────────────────────────────────────────────────────────────────┘
```

- Raw、Lance、标注、清洗、审核和发布查看共享结构，仅替换数据适配器和工具面板。
- 只读模式不是把控件全部置灰；应明确显示“只读”并隐藏不适用的编辑动作。
- 中部可视区保留稳定尺寸，加载/空态/错误态不得引发布局跳动。
- 长列表超过 50 项时在实现阶段评估虚拟化；大时间序列按视口聚合/降采样。

## 8. 组件与交互规则

- 使用现有 Ant Design 基础和 Lucide 图标，不同时引入另一套图标语言。
- 导航使用 `<Link>`/链接语义；动作使用 `<button>`，不使用可点击 `div`。
- 图标按钮必须有可访问名称；装饰图标从辅助技术中隐藏。
- 所有表单使用可见标签、稳定 `name`、正确 `autocomplete`/`inputmode` 和就地错误信息。
- 异步动作开始后显示加载并防止重复提交；完成、失败和超时都提供下一步。
- 危险动作使用确认或可撤销窗口；发布、权限撤销和生命周期动作明确影响范围。
- Tooltip 不能承载唯一关键信息，也不能只支持鼠标悬停。
- 动效只使用 `transform`/`opacity` 等合成友好属性，150–250 ms，并支持 `prefers-reduced-motion`。
- 加载超过 300 ms 使用稳定尺寸的骨架或进度反馈。
- 长文本、超长项目名、任务名、用户名和 ID 必须有换行/截断及查看全文路径。

## 9. 图表与数据可视化

- 趋势使用折线；类别比较使用排序条形图；目标存在时才使用 Bullet Chart。
- 自动质检异常在时间序列上使用形状标记和文字注释，不能只靠红色点。
- 不用漏斗表现并不存在严格转化关系的业务阶段。
- 不使用仪表盘式 Gauge 堆砌 KPI；无目标阈值时用数字、趋势和状态说明。
- 超过 6 条趋势线时拆分或允许选择；超过 1,000 点时在实现阶段启用 Canvas/聚合/降采样。
- 每个图表提供可读标题、单位、图例、精确值交互和表格/文字摘要。
- 图表加载失败必须有重试；空数据解释统计范围和下一步。

## 10. 内容语言

- 面向用户写“采集条目、上传记录、自动质检、提交审核、冻结发布”，不直接以内部代码命名操作。
- 一个动作在按钮、对话框、Toast 和审计结果中使用同一名称。
- 错误说明“发生了什么 + 如何处理”，不只写“操作失败”。
- 任务码明确标注为归类码，不是登录码、设备认证或数据唯一标识。
- `SAVED`、云端已接收和 QC 结果必须分别命名和显示。

## 11. React/Vite 实现约束（效果确认后启用）

- 项目是 React 19 + Vite，不套用 Next.js Server Component、Server Action 或 `next/dynamic` 规则。
- 路由和重型可视化组件使用静态可分析的 `React.lazy`/动态导入进行分包。
- Browser Mock 只在明确的 Mock 模式动态加载，不能进入生产包的默认链路。
- 并行请求消除瀑布；高频光标/播放状态使用局部订阅或 ref，避免整页重渲染。
- 派生状态在渲染阶段计算，不用 Effect 复制；昂贵计算先测量再缓存。
- 大列表和大时间序列先做性能剖析，再决定虚拟化和降采样。
- 不在页面组件内定义子组件；避免无必要的 barrel import 和整库导入。
- 图片/Logo 明确尺寸，重型内容延迟加载，保留布局空间避免 CLS。

## 12. 页面状态合同

每个效果图域至少覆盖：

1. 正常数据。
2. 首次进入加载。
3. 空数据。
4. 部分数据失败。
5. 全部失败且可重试。
6. 无项目权限。
7. 有查看权限但无动作权限。
8. 后端能力未开放。
9. 长内容和大数据量。

状态页面必须保持相同信息架构，不能为不同权限复制新页面。

## 14. 用户评审后的不可变产品覆盖规则

- BrandMark 必须直接渲染 `frontend/src/assets/hangcha-logo.png`，Logo 不能由 CSS、SVG 临摹或生成模型重绘。
- 注册页只收用户名和密码；注册成功即空账户。项目和能力通过后续申请获得。
- 导航只显示功能入口：“数据上传”包含记录 Tab，“数据标注”包含数据修订和 Tag 审核模式。
- P20 只有进行中/已关闭主状态，不分派、不排期、不暂停；相机/Topic 由上传 Manifest 自动发现。
- 数据标注工作台的相机区域按发现数量自适应并同时可见；所有流共享一个时间光标和时间轴。
- Tag 编辑必须呈现可理解的层级路径、Schema 版本、属性和区间；审核面板以 Tag 规则为中心。
- 容量颜色只编码 Raw、标注完成、待标注、问题数据四种业务状态；不编码热/冷/归档层。
- 生命周期策略没有“模拟影响”视图；生产安全通过服务端校验、授权、确认、审计和恢复设计实现。
