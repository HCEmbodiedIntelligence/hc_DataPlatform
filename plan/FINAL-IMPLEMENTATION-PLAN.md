# 具身智能数据平台前端实施与 API 需求计划

> 状态：当前执行入口
> 实施仓库：`../frontend`
> 计划目录：当前目录（仓库内 `plan/`）
> 范围：P01–P19 前端页面，以及这些页面向未来后端提出的接口需求

## 1. 本计划的边界

本计划只交付两类成果：

1. P01–P19 的前端页面、路由、交互、状态、Mock 和测试。
2. 前端页面所需的 API 请求草案，包括 Method、Path、请求、响应、分页和错误形状。

本计划 **不定义也不实施后端业务**。未经用户确认，不得在计划或实施仓库中增加：

- 后端领域模型、数据库、迁移或事务设计；
- 后端状态机、业务规则和数据所有权；
- Worker、Outbox、SSE、队列、DLQ、缓存或部署方案；
- 后端权限计算、审计 producer、对象存储实现；
- FastAPI 或其他后端实现代码。

API 草案表示“前端需要什么”，不表示后端必须按照某种内部方式实现，也不表示业务已经批准。

## 2. 权威阅读顺序

1. 本文件：总体边界、实施阶段和完成标准。
2. `frontend/frontend-page-*-development-plan.md`：P01–P19 的逐页开发计划、API 需求和验收标准。
3. `../docs/FRONTEND-UI-REFACTOR-PLAN.md`：当前仓库内的 UI 实施与收口记录。
4. `../docs/FRONTEND-UI-BASELINE.md`：当前仓库内的逐页视觉与验收基线。

本目录只保留现行计划正文，不捆绑截图、原型、接口 Schema、执行规格或历史台账。

任何接口或业务含义未由用户确认时，前端必须使用 Mock 或明确的 `feature-unavailable`，不得宣称真实联调完成。

## 3. 实施阶段

### 阶段 0：页面和工程基线

- 确认 P01–P19、21 条活动路由和对应设计稿。
- 建立 React、TypeScript、Router、Query、Mock、测试和构建基线。
- 记录已有工作区修改，避免覆盖。

### 阶段 1：前端共享能力

- Shell、导航、Scope 表现、错误状态和权限表现。
- API Client、运行时 Schema、Adapter、Query Key 和 Mock。
- UI Provider、主题、公共组件和响应式基础。

### 阶段 2：P01–P19 页面实现

- 按逐页执行规格完成页面布局、交互和前端状态。
- happy、empty、error、forbidden、conflict、unknown 和 feature-unavailable 可验证。
- 后端尚未确认的操作只展示 Mock 或不可用状态，不制造真实成功语义。

### 阶段 3：前端 UI 收敛

- 统一主题、Shell、Scaffold、表格、筛选、Drawer、Modal 和状态组件。
- 完成 1440、1024、768、390、键盘、焦点和无障碍验证。
- 删除重复前端组件和无作用域 CSS。

### 阶段 4：API 需求整理

- 从页面反推接口清单，保留 Method、Path、请求、响应和错误需求。
- 为每个接口标明消费页面、触发动作和 Mock 场景。
- 删除数据库、事务、Worker、后端领域和部署假设。
- 未确认内容统一标记 `draft / user-confirmation-required`。

### 阶段 5：等待真实后端后联调

只有用户完成业务确认并提供真实后端后才能开始：

- 关闭 Mock，连接指定环境；
- 核对真实接口版本与前端草案差异；
- 验证认证、Scope、分页、错误和写操作；
- 单独记录真实联调和验收结果。

阶段 5 不包含在当前前端交付完成度中，也不得提前宣称完成。

## 4. 当前完成口径

- 页面或组件存在，只能说明前端原型已实现。
- Mock、合同测试和 E2E 通过，只能说明前端自洽。
- OpenAPI 文件存在，只能说明前端接口需求已记录。
- 只有连接用户确认的真实后端并通过验收，才能写“真实联调完成”。
- 本仓库不再使用后端 operation 数量、数据库测试或后端域覆盖率衡量当前计划完成度。

## 5. 前端完成标准

一个页面完成时必须满足：

1. 页面路由、布局、主要交互和响应式可用。
2. Route、Query Codec、API Client、Schema、Adapter 和 Query Key 边界清楚。
3. Mock 正常与主要失败场景可验证。
4. 未确认业务明确显示为不可用或草案，不伪造生产成功。
5. TypeScript、单测、Lint、Build 和对应 E2E 通过。
6. 页面需要的 API 已记录为前端需求，并能追溯到页面操作。

## 6. 禁止事项

- 不得根据 API 名称推导并实现后端业务。
- 不得把前端状态机描述成后端内部状态机。
- 不得新增后端代码、迁移、Docker 服务或后端测试。
- 不得把 Mock-ready 写成 production-ready。
- 不得在用户确认前把接口草案称为冻结合同。
