## 1. 用户已确认的覆盖项

| 决议 | 最终规则 | 被覆盖的旧设计 |
|---|---|---|
| UXF-01 品牌 | 所有页面直接复用 `frontend/src/assets/hangcha-logo.png`；禁止生成、重绘或复制另一套 Logo | E01–E10 中生成的六边形 `HC` 占位 Logo |
| UXF-02 注册 | 用户名和密码直接注册；不需要管理员、邮箱或手机号审批/验证；注册后立即得到空账户 | `PENDING` 账户审批、个人私有项目自动创建、邮箱/手机号验证 |
| UXF-03 授权 | 新账户默认无项目、无业务权限；只有“申请加入项目”和“申请权限”需要审批 | 审批用户注册、审批账户本身 |
| UXF-04 页面复用 | 导航按功能组织；“数据上传”内含“新建上传/上传记录”；“数据标注”承接标注、数据修订和 Tag 审核 | 独立“上传记录”导航、独立“数据清洗”页面、按权限复制页面 |
| UXF-05 P20 任务 | 采集任务不分派人员、PICO 或机器人；不设置开始/结束时间；不支持暂停/继续；创建后持续有效，直至关闭 | 分派模型、有效期、暂停/恢复状态机 |
| UXF-06 P20 创建 | 列表页右上角“新建采集任务”，在同页右侧抽屉创建；字段为项目、名称、自动编号、类型、场景、任务描述、采集目标、质量阈值 | 单独创建页面、必需模态/Topic 字段 |
| UXF-07 数据来源 | 相机、模态和 Topic 不在任务创建时预设；上传后从数据包 Manifest/Topic 元数据自动识别 | P20 手工配置相机/Topic、固定相机数量 |
| UXF-08 标注工作台 | 自动识别到的相机同时显示；所有相机已对齐并共享一条时间轴，不为每个相机重复列视频轨道 | 单视频切换、每相机一条重复时间轴 |
| UXF-09 多级 Tag | 标注支持明确的多级 Tag 路径、层级切换、子标签、属性和区间；示例为一级操作阶段→二级抓取动作→三级抓取成功 | 单一平面标签选择器 |
| UXF-10 Tag 审核 | 审核阶段默认上游完整性与时间对齐已通过；审核重点是层级、边界、必填属性、互斥冲突、动作对象关系和 Schema 版本 | 再次以相机/状态一致性为主要审核内容 |
| UXF-11 容量 | 容量按 Raw、标注完成（清洗完成）、待标注（待清洗）、问题数据展示；不展示冷热/中容量 | 热存储、冷存储、归档容量分级 |
| UXF-12 生命周期 | 不提供“模拟影响”页面或操作；策略直接配置并保留变更审计与 Raw/Manifest 保护 | 影响模拟 Tab、模拟结果抽屉 |

## 2. 最终功能信息架构

| 功能域 | 导航入口 | 页面/模式 | 说明 |
|---|---|---|---|
| 采集与接收 | 采集任务 | P20 列表、详情、创建抽屉 | 只定义任务，不分派人或设备；实际来源由已接收 Manifest 追溯 |
| 采集与接收 | 数据源 | P02 | 管理允许的数据来源/连接器，不复制机器人资产页 |
| 采集与接收 | 数据上传 | P03 新建上传、上传记录；P04 摄取/QC 详情 | 一个功能页两个 Tab；上传完成后进入记录和摄取详情 |
| 数据生产 | 数据集 | P05–P07 | 浏览、采集条目、版本审核和冻结发布 |
| 数据生产 | 数据标注 | P08 标注模式、数据修订模式、Tag 审核模式 | 标注与清洗为同一功能；P11 旧入口只做兼容跳转，不出现在新导航 |
| 数据生产 | 质量问题 | P09 | 展示已进入 Lance 后发现的问题；Raw 自动质检异常仍回 P04/Raw 诊断 |
| 数据生产 | 标注任务 | P10 | 标注任务队列；是否分配标注任务与 P20“不分派采集任务”是两套独立规则 |
| 治理与资产 | 容量管理/生命周期策略 | P12/P13 | 容量按业务数据状态；生命周期无影响模拟，保留保护规则与审计 |
| 治理与资产 | 机器人资产/标定/Schema | P14–P17 | 资产、实例、标定和数据契约管理 |
| 安全与审计 | 账户与权限/审计日志 | P18/P19 | 仅审批加入项目和权限申请；注册本身不审批 |

## 3. 仍需产品确认的问题

这些问题未从效果图中擅自推断，确认前不得写死到正式合同。

| 编号 | 问题 | 推荐选择 | 不确认会阻塞 |
|---|---|---|---|
| OPEN-01 | 无邮箱/手机号时如何找回账户？ | 管理员线下核验后签发短时一次性重置凭据，并完整审计 | 公网账户恢复、客服流程、安全验收 |
| OPEN-02 | 是否需要注册验证码、IP/设备限流和密码尝试锁定？ | 需要：验证码 + 分层限流 + 渐进延迟；不改变“注册无需审批” | 公网注册/登录上线 |
| OPEN-03 | “申请权限”是否必须先加入目标项目？ | 必须先成为项目成员；全局平台权限走独立管理员流程 | P18 状态机和越权测试 |
| OPEN-04 | 关闭采集任务后能否重新打开？ | V1 不允许重新打开；需要继续采集时复制为新任务 | P20 状态机、审计和幂等 |
| OPEN-05 | 采集目标是数据包数量、总时长，还是允许二选一？ | 至少填写一项，可同时填写；达到目标只提示，不自动关闭 | P20 验证规则和进度公式 |
| OPEN-06 | 质量通过阈值是否属于任务字段？ | 保留为项目默认值的可覆盖项，范围 0–100% | P20 创建合同、P01 进度、验收样例 |
| OPEN-07 | 多级 Tag 最大深度和每级必填规则？ | V1 最大 5 级；Schema 决定必填层级和属性 | Tag Schema、编辑器与验证器 |
| OPEN-08 | Tag 审核是否禁止自审？ | 禁止提交者审核自己的修订 | 审核权限、审计和 E2E |
| OPEN-09 | 容量四类是否互斥，问题数据是否同时属于 Raw/待标注？ | 图表主口径互斥；问题数据单列，另提供“物理占用总量”避免重复 | P12 聚合公式与容量对账 |
| OPEN-10 | 无“模拟影响”后，危险生命周期变更是否需要双人复核？ | UI 不模拟；生产危险策略仍需二次确认和双人批准 | P13 命令合同、Worker 与生产安全 |

## 5. 推荐启动顺序

1. 先确认 OPEN-01～10，不直接按旧 E1 图编码。
2. 第一条工程关键路径：`F1-01 → F2-01 → F4-01/F4-02`，先建立公网账户与真实 scope 安全边界。
3. 第二条业务主链：`F1-02/F1-03 → F2-02/F2-03 → F3-01 → F4-03/F4-04`，先让任务和上传使用真实数据。
4. 第三条数据生产主链：`F1-04 → F2-04 → F3-03 → F4-05/F4-06`，实现 Manifest 驱动多相机和多级 Tag。
5. P01 与容量依赖上述事实模型，放在 `F3-02/F3-04` 后接入；不要先写新的 Mock 聚合。
