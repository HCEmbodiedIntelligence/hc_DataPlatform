## 3. “尽量还原”的可执行定义

### 3.1 必须还原

- 页面区域顺序、主次关系、分栏比例、卡片/表格/抽屉位置和唯一主动作位置。
- 最新图中的功能命名和用户已确认的操作删改，例如无独立清洗、无分派、无任务时间窗、无暂停/继续、无账户注册审批。
- expanded/collapsed Shell 的整体观感、官方 Logo、项目/区域上下文、页标题、筛选、主内容和右侧工具区。
- 高密度桌面工作台的层级：14 px 正文、紧凑表格、8 px 基础间距、稳定的 16/24 px 区域间距。
- 加载、空态、局部失败、无权限和能力未开放时保持同一页面骨架，不产生布局跳动。

### 3.2 不应机械复制

- 不从 PNG 取色后在组件中散写 Hex；使用 `frontend/src/app/theme/` 的语义 Token。
- 不复制效果图里的假 ID、假统计值、假用户、假相机数量或假审计结果。
- 不把图片里的机器人/相机画面打包为生产数据。视觉测试可使用明确标注的测试素材。
- 不重画 Logo；只能引用 `frontend/src/assets/hangcha-logo.png`。
- 不为追求像素一致而破坏 1280 可用性、真实字段长度、权限控制、错误状态或键盘操作。

## 4. 全局尺寸与 Token

### 4.1 浏览器验收尺寸

- 主验收：1440×900，浏览器缩放 100%，设备像素比 1。
- 次验收：1280×800，浏览器缩放 100%，设备像素比 1。
- 效果图对照：只在 1586×992（E01 为 1536×1024）做人工叠图，不把 AI PNG 直接设为 Playwright 像素基线。
- 1280 不允许整页横向滚动；表格和时间轴只能在自己的受控容器内滚动。

### 4.2 Shell 几何

- 顶栏高度：68 px，沿用当前 `PlatformShell`。
- 展开导航宽度：218 px；折叠导航宽度：64 px。
- 页面主区域水平内边距：1440 使用 24 px，1280 使用 16 px。
- 区块栅格：12 列，列间距 16 px；纵向大区块间距 16 px。
- 页面标题行最小高度 48 px；一个页面最多一个高强调主 CTA，放在标题行右侧或主流程尾部。

### 4.3 表面、文字和交互

- 页面背景、Surface、Border、Text、Primary、Focus、状态色全部沿用 `design-system/hc-data-platform/MASTER.md` 和现有 `--hc-*` Token。
- 默认正文 14 px/1.5，帮助文字 12 px，区块标题 16–18 px，页面标题 24–28 px；技术值才用等宽字体。
- 卡片圆角优先 10/12 px，边框 1 px；阴影只用于抽屉、弹层和高层级浮层。
- 紧凑控件高度优先 32/36 px，主按钮可为 36/40 px；禁止全站大胶囊按钮。
- 点击目标最小 32×32 px；所有图标按钮有可访问名称和可见焦点。
- 动效 150–250 ms，仅使用 `transform`/`opacity` 等合成友好属性，并遵守 `prefers-reduced-motion`。

## 5. E01–E10 页面视觉合同

### E01｜认证与账户状态

- 无业务 Shell。桌面分为约 64% 主认证区、约 34% 状态预览区，中间留 16–20 px 间隙。
- 主认证区采用浅色工业网格/线稿背景；官方 Logo 与“HC 数据平台”在左上主视觉区，登录卡位于主区右半。
- 登录卡最大宽度约 420 px，垂直居中；只显示用户名、密码、记住我、忘记密码、登录、创建账户。
- 注册表单只收用户名和密码/确认密码；不出现邮箱、手机号、验证码或管理员审批。
- 注册成功和空账户是同一认证视觉系统的状态卡。空账户主动作是“申请加入项目”，次动作是“申请权限”。
- 生产实现不需要把三种状态同时铺在同一浏览器页面；E01 右侧状态卡用于展示状态序列，代码可通过独立路由/状态稳定复现。

### E02｜全局 Shell

- 展开导航 + 68 px 顶栏；官方 Logo 与平台名置于导航品牌区。
- 顶栏从左到右：项目、区域；右侧为搜索/通知未开放提示、账户菜单。未开放控件不能伪装可用。
- 导航按功能分组；“数据上传”是唯一上传入口，“数据标注”承接修订和 Tag 审核，不出现独立“上传记录”或“数据清洗”。
- 页面加载使用与最终内容同构的骨架：上方摘要卡、下方列表/图表区，不能使用只有居中 Spinner 的空白页。

### E03｜P01 工作台

- 标题行右侧依次为时间范围、测试/演示数据标识（只在测试环境）、`as_of` 和刷新。
- 顶部“信号轨道”占首屏内容高度约 34%–38%，横向展示采集、已接收、自动质检、30 Hz 对齐、Lance、数据标注、审核、已发布。
- SAVED 与已接收分开；自动质检异常下方提供 Raw 诊断入口；数据标注不拆出清洗节点。
- 下半区约 2/3 为“我的待办”，约 1/3 为“最近活动”和局部失败提示；局部失败不能清空其他卡片。
- 待冻结发布的操作文案固定为“进入发布”。

### E04｜P20 采集任务

- 使用折叠导航。主区约 66%，右侧创建抽屉约 34%；抽屉宽度使用 `clamp(440px, 34vw, 540px)`。
- 主 CTA“新建采集任务”固定在标题行右侧；点击后同页打开抽屉，不跳转独立创建页。
- 主区顺序：标题/说明、筛选、搜索、任务表格、分页。表格优先显示名称/编号、状态、项目、类型、数据包进度、质量通过率、最近提取时间、操作。
- 抽屉只包含项目、任务名称、自动任务编号、采集类型、采集场景、任务描述、采集目标、质量通过阈值。
- 禁止出现分派、执行人员/PICO/机器人、开始/结束时间、暂停/继续、模态/Topic 配置。

### E05｜数据上传

- 展开导航。页内只用“新建上传 / 上传记录”两个 Tab。
- 新建上传桌面三栏：左侧上传方式和目标信息约 25%，中间 Manifest 预检约 50%，右侧上传队列约 25%。
- 中间预检区是视觉重心，展示标识关系、校验、预计体量、自动发现相机/Topic 和文件组成；相机/Topic 只读。
- 队列展示分片进度、速度、剩余时间、暂停/取消/重试失败分片；这里的暂停只针对上传传输，不是 P20 任务暂停。
- 页底安全提示和主动作保持稳定；公网环境必须表达格式/大小/敏感信息/审计约束。

### E06｜Raw 诊断工作台

- 使用折叠导航。内容区约为：左 18% 采集条目，中 53%–58% 多相机/信号，右 24%–28% 质量发现和诊断备注。
- 顶部异常横幅说明“异常数据保留在 Raw，不进入 Lance”；只读标签清楚可见。
- 中部相机按 Manifest 自动发现并自适应；E06 正常参考态可为 2×2，但实现不能硬编码四路。
- 所有相机、关节状态、动作指令和自动质检状态共享一个时间光标。底部可有多条信号轨道，但视频播放时间轴只能有一个。
- 诊断备注不改变自动质检结果；动作入口是复制证据、请求重采或重新运行允许的自动校验。

### E07｜数据标注工作台

- 复用 E06 的 viewer 内核。左侧采集条目约 18%，中部 viewer/时间轴约 58%，右侧 Tag 工具约 24%。
- 相机由 Manifest 自动发现并同时可见；0/1/2/4/N 路通过栅格和折叠策略适配，所有流共享时间光标。
- 右侧必须直接看到多级 Tag 路径、树形层级、Schema 版本、必填属性、区间和对象关系；不能只给一个平铺标签下拉框。
- 底部仅一个共享时间轴，区间与关节/动作曲线对齐；主动作是“保存草稿”和“提交审核”。
- 清洗/修订是数据标注中的模式，不创建独立清洗页面或导航。

### E08｜Tag 审核

- 复用 E06/E07 viewer 内核；左约 18%，中约 54%，右约 28%。
- 中间使用单个主视频/当前相机 + 原始/修订区间同轴对比；其他相机通过 viewer 切换或联动查看，不复制时间轴。
- 右侧审核清单以 Tag 为中心：层级、边界、必填属性、互斥/冲突、动作与对象关系、Schema 版本。
- 显示当前时间戳的多级路径和属性，以及原始/修订差异；通过、要求修改、拒绝必须有清晰权限和确认反馈。
- E08 不再称“清洗审核”，页面归属“数据标注 / Tag 审核”。

### E09｜项目与权限审批

- 使用折叠导航。标题下方使用项目加入申请、权限申请、用户、项目成员、权限模板等功能 Tab，不创建角色专用页面。
- 主内容约 62%，审批抽屉约 38%；主内容内部为申请列表 + 申请详情两栏。
- 只审批“加入项目”和“权限申请”；不出现账户注册审批。
- 审批抽屉分成申请项目/角色、请求权限/数据范围、风险提示、审批决策和必要的高风险再认证。
- 效果图中的邮箱/手机号只是身份详情示例，不得重新引入注册验证要求。

### E10｜容量与生命周期

- 展开导航。页面主体左右约 46%/54%：左侧容量管理，右侧生命周期策略与变更审计。
- 容量总览按 Raw、标注完成、待标注、问题数据四类显示；不出现热/冷/中容量或费用。
- 左侧顺序：总览与四类图例、增长趋势、项目容量明细。图表必须有单位、文字摘要和可访问替代。
- 右侧顺序：策略列表/搜索/筛选、保护策略、变更审计。无“模拟影响”按钮、Tab、抽屉或 API 调用。
- Raw、Manifest、已发布 Manifest 的保护必须在策略和审计中可见；危险执行的后端校验不等于前端模拟页面。

## 7. 视觉验收与截图门禁

每个页面所有者必须交付：

1. 1440×900 正常态截图。
2. 1280×800 正常态截图。
3. 至少一个加载/空态/局部失败/无权限截图，保持同一布局骨架。
4. 效果图对照说明：完全还原项、因真实合同/响应式/可访问性产生的差异、仍未完成项。
5. 键盘 Tab 顺序、可见焦点、对比度、`axe` 和整页横滚检查结果。

推荐 artifact 路径：

```text
artifacts/visual/e01-e10/E01/1440x900.png
artifacts/visual/e01-e10/E01/1280x800.png
...
artifacts/visual/e01-e10/E10/1440x900.png
```

测试策略：

- 首次实现使用人工叠图确认区域几何和视觉层级；AI 效果图不直接作为像素 diff baseline。
- 用户确认代码截图后，再将真实浏览器截图设为 Playwright baseline；后续建议 `maxDiffPixelRatio <= 0.015`，动画、时间和视频帧必须稳定化。
- 视觉测试可使用测试专用确定性数据和网络拦截，但 `VITE_MOCK_MODE=off` 的真实 API E2E 必须另行执行，且失败不得回退 Browser Mock。
- E06–E08 额外测试 0/1/4/8 相机、缺流、慢流、超长 Tag、时间轴同步和 1280 性能。

## 8. 前端设计自审

实现完成后逐页回答：

- 第一眼是否能看出当前业务阶段、异常和下一步动作？
- 是否出现了效果图没有要求的巨大标题、渐变、胶囊、漂浮卡片或装饰动效？
- 页面是否仍像机器人数据操作台，而不是通用后台模板？
- 是否用卡片把本可用分组/表格表达的内容全部包了一层？
- 是否把权限差异实现成了重复页面？
- 是否为了像效果图而隐藏了真实错误、长文本、大数据或无权限状态？
- Logo、Tag 层级、共享时间轴、P20 禁用字段和四类容量是否全部符合用户最终反馈？
