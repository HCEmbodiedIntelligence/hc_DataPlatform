# Production completion checklist

Updated: 2026-08-24 (Asia/Shanghai)

This is the living implementation and verification ledger for the production-completion
objective. A row is complete only when its database, backend, authorization/audit, frontend,
contract, targeted tests, affected regression, and real-dependency/browser evidence all pass.
Historical reports are discovery inputs, not current proof.

Status meanings: `NOT STARTED`, `INVENTORY`, `IN PROGRESS`, `BLOCKED`, `VERIFIED`.

## Worktree and verification rules

- Preserve every pre-existing staged, unstaged, and untracked change. Do not reset or restore
  files to HEAD merely to make a gate pass.
- Run tests fail-fast: pytest `-x`, Vitest `--bail=1`, Playwright `--max-failures=1`; stop at
  the first lint/type/build failure.
- Record exact commands and first-failure/fix/retest evidence in the verification log below.
- `VITE_MOCK_MODE=off` and direct network evidence are mandatory for final browser acceptance.
- A legitimate unsupported input format is not an unfinished feature. A promised product
  capability represented by 501, a placeholder, a disabled action, or Mock-only success is.
