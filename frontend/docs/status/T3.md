### P03 上传任务 `/ingest/uploads`

- P03 是数据接入分组默认合法落点；列表提供服务端筛选、稳定排序、游标分页、状态 Tab、批量暂停/取消和创建上传入口。
- 批量写按资源逐项发送 ETag、If-Match 与独立 Idempotency-Key；取消二次确认且不乐观删除。
- AsyncJob 使用 `shared/jobs/use-async-job.ts`；scope SSE 只作加速，5 秒轮询为事实兜底，resourceVersion/eventId 去重。
- 行进度文本使用 100ms 节流（不超过 10Hz），进度数值不使用 `aria-live` 刷屏。
- 直传模块包含：内存授权/File vault、no-store OSS transport、single-flight 续签协调器、授权过期仅刷新重试一次、服务端 policy 并发/重试、ListParts 恢复对账、Multipart runner、SHA-256 Worker port、非敏感恢复描述白名单。

### P04 上传详情 `/ingest/uploads/:uploadId`

- 隐藏详情路由，`navigationOwnerPageId: 'P03'`，继承 P03 导航 active 态；`latest/current` 在 builder 与页面 guard 双重拒绝。

## 第 13 节状态矩阵

统一 `IngestRegion` 和 ingest mock scenario 对工程基线的 13 行状态逐项建模；状态可以是页面级或独立区域级，写操作在不安全状态默认禁用。

| 基线状态 | 组件状态 / Mock | 覆盖结论 |
|---|---|---|
| first-loading | `first-loading` | 固定区域 loading，禁止伪造 0 |
| refreshing | `refreshing` | 保留旧数据并标记 `aria-busy` |
| empty / filtered-empty | 两个独立状态与 scenario | 明确区分并提供清筛选动作 |
| partial-error | `partial-error` | P02 component error、P04 对象/事件区域独立失败 |
| fatal-error | `fatal-error` | 安全错误、重试入口 |
| forbidden | `forbidden` | capability gate 在领域 query 前生效 |
| not-found / gone | 两个独立状态与 scenario | 404 与 410 不合并 |
| conflict | `conflict` / `etag-conflict` | 不覆盖新事实，不自动重放危险写 |
| rate-limited | `rate-limited` | Fixture 提供 Retry-After，禁止高频自动写重试 |
| offline / reconnecting | `offline-reconnecting` / `offline-recovery` | 陈旧数据只读、轮询/SSE 恢复 |
| contract-mismatch | `contract-mismatch` | Zod/秘密字段检测阻断区域 |
| unknown-enum | `unknown-enum` | 新连接器/生命周期/阶段只读，mutation 禁用 |
| feature-unavailable | `feature-unavailable` | 无有效 scope/运行时能力时不渲染半成品写流程 |

另有正常 `ready` 状态；Mock 还覆盖 validation-error、preflight-blocked、submitting、accepted-job、job-failed、duplicate-idempotency、permission-revoked、signed-url-expired、sse-disconnected、scope-switch-race 等写流程状态。

## 未冻结假设

- 连接器 V1 暂定 `ROBOT | EDGE_AGENT | OSS_IMPORT`，capability 与字段以机器合同当前版本为准；任何新 discriminator 进入 `UNKNOWN` 安全投影且不可编辑。
- 校验流水线暂定六阶段：`MANIFEST_SCHEMA -> OBJECT_EXISTENCE_SIZE -> OBJECT_SHA256 -> ADAPTER_PARSE -> DATASET_SCHEMA_SEMANTIC -> ATOMIC_AVAILABILITY_COMMIT`。未知阶段不推测顺序并禁用释放/复验写操作。
- 隔离不直接调用“release”端点；V1 将用户“释放”意图实现为 append-only `retry-verification`，仅服务端原子 AVAILABLE 提交成功后改变 disposition。
- 删除数据源没有已冻结后端 DELETE 合同，因此只展示稳定 ID、影响和 blocked reasons 的 fail-closed 确认面，不发送伪造请求、不乐观删除。
- 创建选项没有“允许未绑定 Dataset”的显式标志，因此 UI fail closed，要求选择创建选项中的可用 Dataset。
- P04 的“审计摘要”只展示安全 Upload resource events 与 requestId/jobId 关联，不冒充 P19 正式审计投影。
- 后端没有 batch pause/cancel endpoint；前端使用逐资源 fan-out，保持每个资源独立 CAS 与幂等意图。
- scope ingest SSE endpoint 暂按 `${VITE_SSE_BASE_URL}/ingest/events`；它只触发按 resourceVersion 收敛/重取，旧事件不能覆盖 Query 快照。
- OSS provider 签名与续签响应仍是 adapter seam；页面和 ViewModel 永远不接收 STS、签名 URL、Bucket 或完整 OSS key。
