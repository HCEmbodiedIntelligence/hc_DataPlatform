## 合同与安全边界

- ManualIssue 与 ReviewFinding 使用独立实体、DTO、状态、Query Key、capability、mutation 和审计语义；两实体模块无互相导入。
- Issue → Draft 的浏览器请求 body 固定为空，仅由路径和 `Idempotency-Key`、`If-Match` 表达 `manualIssueId + idempotencyKey + expectedVersion`；只使用响应 `draftId` 构造 P11 路由。
- P11 不写 Finding API，也不调用 Review mutation；Review Return 仅作为不可变定位与血缘投影。
- 全部时间范围采用 `[startNs, endNs)`；纳秒经 `bigint-string`/EDL decimal helper 处理，未使用 `Number()`。
- Commit 不乐观推进，必须具备稳定 draftId、READY 且未陈旧的 Preview、EDL revision/hash、capability/allowed action，并通过展示影响摘要和 `blocked_reasons` 的确认对话框；请求携带 `Idempotency-Key` 与 `If-Match`。
- Mock fixture/handler/scenario 覆盖 happy、empty、forbidden、conflict、contract mismatch、unknown enum、Review Return、Preview/Commit 阻断等状态。
