# ADR-0004：参考 New API 补齐账户认证闭环

- 状态：Accepted（2026-08-24 按最新产品管理员规则修订）
- 日期：2026-08-21
- 参考项目：[QuantumNous/new-api](https://github.com/QuantumNous/new-api)
- 参考版本：`f116414284162ad15d8925f7bca494c109b83e93`
- 上游许可证：GNU AGPLv3，并包含上游 `LICENSE` 所述的附加署名条款

## 决策

本项目参考 New API 的登录、邮箱验证、忘记密码、会话管理、权限目录和
Cloudflare Turnstile 接入流程，在 FastAPI/PostgreSQL 架构中独立实现等价能力。
参考信息只记录在本文档；产品页面和业务源码不放置上游署名。

不会逐行移植 Go/Gin/GORM 源码。原因除了语言和框架不同，还包括本项目已有更严格的
组织/项目 capability、PostgreSQL RLS、凭据版本和审计模型，直接复制会削弱现有边界。

## 第一批采用的逻辑

1. 忘记密码请求始终返回相同的接受结果，不能据此枚举账号或邮箱。
2. 开启 Turnstile 时，发送恢复邮件必须先通过人机验证，并受公共认证限流约束。
3. 邮箱验证和密码恢复令牌为高熵、单次、限时令牌；数据库只保存 SHA-256 摘要。
4. 忘记密码确认只需要恢复令牌和新密码，不需要原密码。
5. 恢复成功后提升凭据版本并撤销该账号的全部旧会话。
6. 已登录主动修改密码仍要求原密码；它和忘记密码是两个独立流程。
7. 恢复链接把令牌放在 URL fragment 中，避免浏览器首次请求、网关 access log 和
   `Referer` 自动携带令牌；前端后续只把令牌放入确认接口的请求体。
8. 恢复令牌绑定签发时的凭据版本；主动改密、账号禁用等凭据变更会使旧令牌失效，
   更换恢复邮箱时也会消费旧邮箱签发的未使用令牌。

## 与参考实现的有意差异

New API 参考版本中的找回验证码保存在进程内存，重启或多节点部署会丢失；重置接口还会
生成并返回明文随机密码。本项目改用 PostgreSQL 持久化的哈希令牌，并由用户提交符合
当前密码策略的新密码，不在日志、数据库、邮件投递记录或 API 响应中返回密码明文。

## 第二批：平台用户管理

参考 New API 管理端的用户分页、搜索、创建、启用/禁用、角色层级和危险操作确认，新增
HC 平台自己的管理员用户管理闭环：

1. `platform.account.read`、`platform.account.manage` 与
   `platform.account_security.manage` 是全局授权，不由任何项目管理员角色隐式获得。
2. 管理员可按用户名、显示名称、恢复邮箱或 principal ID 搜索，并按账号状态和平台角色
   进行服务端分页筛选；响应不包含密码哈希、令牌或完整恢复邮箱。
3. 创建用户时管理员提供初始密码，密码仅作为 write-only 请求字段，仍由统一的最少 6 位
   密码策略校验。
4. 禁用、管理员重置密码和删除都会立即撤销目标用户的活动会话；管理员重置不要求目标
   用户的原密码，也不会返回临时明文密码。
5. 删除采用软删除，保留历史数据归属、外键和审计记录；管理端查看已删除账号时只返回
   安全投影。
6. 禁止管理员在该入口重置、禁用、降级或删除自己；本人改密必须走需要当前密码的账户
   设置，忘记密码则走恢复令牌流程。另禁止禁用、降级或删除最后一个可用的平台管理员。
7. 普通项目管理员仍只管理其获授权项目，不获得平台账号管理权限。平台管理员角色则必须
   获得全局 `platform.admin`，它在中央鉴权层包含全部平台、组织、项目、区域及业务权限，
   并绕过项目 membership；该包含关系是产品规则，不需要在各业务路由重复判断。
8. `platform.admin` 只允许通过平台角色管理产生，不允许作为项目 capability 申请或按用户
   名动态推断。超级管理员仍只能选择目录中真实存在的组织和项目，资源不存在性检查不变。

`security/015_platform_account_administration.sql` 是已经发布的历史引导迁移，不能修改其
校验和。新规则由幂等迁移 `security/020_platform_super_admin.sql` 前向修正：它根据既有
平台角色 capability bundle（而不是用户名）为所有现存平台管理员补充 `platform.admin`，
只对实际发生补充/恢复的账号提升 capability revision，并撤销其旧会话。迁移后这些账号
必须重新登录；后续平台角色升降级同样会撤销目标账号旧会话。

数据库 RLS 只接受由已验证 `AuthContext` 写入的 `app.platform_admin` 事务上下文。API 层先
从项目目录确认组织/项目真实存在，再选择请求 scope；RLS 的超级管理员分支只取消 membership
行过滤，不能把任意组织或项目标识变成合法资源。

New API 当前参考版本还提供硬删除路径。本项目没有采用该路径，因为机器人数据、上传、
标注、发布和审计事实都需要稳定的 principal 引用。管理页面中的“删除用户”明确表示可
审计的软删除。
