# T10 dependency requests

## Platform foundation alignment

1. The frozen signature promises `app.core.int64.Int64Str`; the current file
   exports `Int64`, `ByteCount`, and `Nanoseconds` only. Domain code currently
   uses a narrow import fallback so it remains loadable. Please add the promised
   alias without changing serialization behavior.
2. The frozen signature promises `InMemoryObjectStoragePort`; the current fake is
   named `FakeObjectStoragePort`. Storage/robotics will use a local import fallback
   until the promised alias is present.
3. `app.core.audit.write_audit` writes `audit_records`, while domain 06 owns the
   required append-only `audit_events` source with unique producer identity,
   retention, Legal Hold and integrity metadata. Please route the platform audit
   port to domain 06's trusted append contract (without introducing a reverse
   domain import) or publish a local Protocol/adapter injection point. Until then,
   other domains' simplified audit rows are not queryable as authoritative P19
   records.
4. `app.core.ids.new_id("request")` is used by `app/main.py`, but `request` is not
   present in `ID_PREFIXES`; requests without a valid `X-Request-ID` fail before
   routing. Please add the frozen request ID kind in the platform-owned file.
5. Access/invitation successful preflight operations are POST endpoints but the
   canonical 142-event catalog has no successful preflight event for them. The
   access contract also calls preflight read-only. Please confirm that the unified
   "all write endpoints write audit/event" rule excludes read-only preflight, or
   approve canonical event names through the registry process; T10 will not invent
   names or misuse `access.change.rejected` for successful requests.
