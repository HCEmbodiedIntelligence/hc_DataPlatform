## 未冻结假设

1. 三份规格仍是 `conditional` / `conditional-review`；当前实现遵守固定 wire 与
   fail-closed 默认，但生产开放仍需 P18 签署 capability/roleVersion/action ceiling，
   P19 签署 event schema、producer、retention 与 outbox relay 策略。
2. Storage inventory/object/multipart facts 由 P03/P04、provider inventory 与
   protection systems 交接；本域不复制 UploadSession/Manifest，也不自行推断
   `UNCLASSIFIED` 或 provider locator。
3. Robot sample candidate、DatasetSchemaSnapshot 的创建分别属于 capture/dataset/
   ingest owner；本域只消费权威、版本化投影，没有增加隐藏写入口。
4. Robotics canonical JSON/hash、frame/quaternion/clock/joint conventions、schema
   primitive/unit/encoding dictionaries仍待平台与数据治理签署；未知值保持拒绝，
   不做隐式归一化。
5. Availability consumer policy维持“显式绑定优先、零个或多个候选均阻断”；V1
   availability mutation、四类下载 intent 与 `data_schema.deprecate` 保持关闭。

## 已知长尾 / 外部依赖

1. T8 共享 `with_idempotency` 当前保存完成结果但不比较 request-body digest；
   “同 key、不同 body 必须 409”的统一修复属于共享 core，三个域均不能在各自
   router 私建不一致实现。
2. AsyncJob 的持久化与轮询投影已实现；真实 worker lease/fencing、SSE、provider
   side effect、retry/backoff/dead-letter、限流与 429 策略仍由 Job/Storage/SRE
   owner 落地。Robotics 的有界同步验证在当前实现中直接形成终态 Job。
3. PostgreSQL serializable/row-lock、并发 preflight consume、binding interval、
   cross-Robot mount、multipart finalize-vs-abort 的真实竞态测试尚需集成数据库；
   当前自动化使用 SQLite 验证事务形状与状态机。
4. T8 `get_context` 会运行时强制 scope/client headers，但这些共享 header 目前不会
   自动出现在 FastAPI 生成的域 OpenAPI parameter 列表；冻结 OpenAPI 仍是客户端
   生成权威。需要 core 提供可复用的、可文档化 header dependency 后统一消除该
   差异。
5. Access 的 identity invitation acceptance、audit relay/quarantine、export
   worker、retention purge/Legal Hold 运维流程；Storage 的 billing/inventory
   watermark、KMS/Object Lock、restore/abort provider fence；Robotics 的 external
   sample/snapshot handoff 均需对应 owner 的联调与故障演练。
