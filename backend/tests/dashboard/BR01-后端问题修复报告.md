## 技术设计

- 复用 BE21 的唯一 Router、Service、Repository、model、HMAC cursor、audit 和索引结构，没有增加
  第二套路由或 schema。
- Dashboard Repository 的事实 SQL 均携带 principal、project、region、`[from,to)`；Service、
  Repository 和 RLS scope 共同拒绝越权，管理员身份不会自动跨区域聚合。
- Activity 固定为四类持久化事实事件：上传提交、QC 完成、Tag 审核决定、数据集发布。稳定事件
  身份、事实时间、去重键、安全展示文本、目标资源和确定性排序记录在 Dashboard README。
- Coverage 无版本化 denominator 时只返回 `P01_COVERAGE_DENOMINATOR_MISSING/BLOCKED`；历史
  observation 只保留为技术查询证据。
- Pending 只联合上传失败、QC 异常、待 Tag 审核、待发布；按 domain severity、最早
  `opened_at`、稳定 source tuple 排序，并与 principal capability 取交集。deep link 仅允许固定
  upload/annotation/dataset 相对路径，并且只引用安全域的 canonical capability
  常量；未写入平行权限名称或 SLA 数字。QC 待办需同时具备 `datasets.read` 和
  `ingest.upload`，保证展示内容与 upload deep link 都可授权。
- 新增 immutable rollout-publication lineage。正向发布在 dataset version 的同一 PostgreSQL
  事务内解析并写入所有 exact project+rollout region；重复发布重入同一校验，并发由 immutable
  dataset key 决出 winner。历史回填只连接确定的 project+rollout，不使用默认 region。
- 已知血缘按 exact project+region+range 计数；同 project/range 存在不可归属历史时降级为
  `PARTIAL`，全无已知血缘时为 `BLOCKED`。
