## 3. 技术设计

1. 响应出口只有一个安全化边界。ProblemException、Starlette/FastAPI HTTPException、未知
   Exception、依赖 503 和直接返回的非标准 5xx 均被投影为安全 Problem Details。5xx 丢弃
   原 detail/details/header；instance 使用路由模板而不是真实资源路径。
2. request id 只接受规范 UUID；其他调用方值由服务端重建，避免把任意 header 当日志字段。
   安全日志消息固定，只记录闭集异常类别、稳定 error code、request id 和路由模板，不记录
   exception message、request body、认证/cookie、DSN 或对象 locator。
3. validation 只返回有界的 error type、请求来源和固定消息；不返回 input、ctx、动态字段名或
   validator message。4xx HTTPException 不透传任意 detail/header；Problem Details 的嵌套结构
   对敏感 key、非 allowlist 错误文本和复杂对象执行递归脱敏。
4. `HC_API_DOCS_ENABLED` 默认 false，staging/production 设置为 true 会配置校验失败。
   FastAPI HTTP schema 路径关闭时仍保留 `app.openapi()` 内部生成能力。
5. 公网 gateway 对 docs/OpenAPI/metrics 精确 fail closed。Helm 使用内部 ClusterIP metrics
   Service；Ingress 的 `/metrics` 指向无端点 deny Service；NetworkPolicy 只允许配置的
   monitoring namespace/pod selector 访问 API 端口，不使用 `X-Forwarded-For` 做鉴权。
6. Prometheus exposition 不输出 principal/project/region/resource/workflow 等 scope 或高基数
   label 样本；低基数 Python/process 指标保留。公开 liveness/readiness 不再暴露环境、依赖名、
   延迟、地址或异常文本。
7. gate runner 在内存中先脱敏 stdout 再落日志；无论主 gate 成功、失败、XFAIL 或 NOT RUN，
   都执行 artifact 原地 sanitizer 和 fail-closed scanner。JUnit failure/error 节点保留，但内部
   failure detail 替换为稳定 marker。
