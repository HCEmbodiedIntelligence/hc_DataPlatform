## 二、技术设计

- `commit-manifest` 在同一 PostgreSQL 事务中提交 Raw/上传状态、`ingest.workflow_triggers`、`core.outbox_events` 和 `core.audit_events`。事务失败不留半成功触发事实。
- workflow ID 由 workflow kind + project + `region/rollout` 确定性编码；outbox event/annotation trigger/task 使用 UUID5 确定性身份。API 只返回已持久化的 workflow locator。
- outbox dispatcher 使用租约 claim、原子完成/重试、稳定错误码和安全审计。Temporal already-started、API 重试、outbox 重投与 worker 重启收敛到同一 execution。
- 没有可验证的持久化 ingest 输入关联时，默认 resolver 以 `INGEST_WORKFLOW_PLAN_BLOCKED` 可观测阻断，不从 UI fixture、seed 或相似 API 推断 dataset/QC/alignment 参数。
- Ingest workflow 仅在 DerivedReady/Lance commit 成功后调用系统 annotation activity。任务唯一键包含 project、region、rollout、dataset/version、Lance version 和 task kind，并发/重放只有一个 winner。
- capability key 集中在 `security/capabilities.py`。AccessService 每次从当前 session 解析 project-scoped capabilities，旧 role 仅通过该表兼容投影，不提供跨 project/region 的 admin 绕过。
- PostgreSQL repository 除 RLS 外再使用显式 `app.project_id × app.region_code` 条件，关闭表 owner/superuser 测试连接绕过 RLS 时的数据泄漏窗口。
- P20 保留 `access_control.audit_events` 兼容查询，并在同一事务内使用同一 event ID 将 project-scoped 安全摘要写入 `core.audit_events`。Ingest staged、workflow dispatch accepted/retry、annotation created/blocked 均写入同一正式事实源。

## 八、OpenAPI/迁移影响与残余风险

- 本终端没有修改 `backend/openapi.generated.yaml`、`backend/migrations/manifest.txt`、`runtime.py`、Compose、`core/app.py`、验收矩阵或前端生成类型。工作树中这些文件的现有改动属其他终端，本 BR 未 reset/checkout/clean/覆盖。
- 迁移依赖 `core.audit_events`、`core.outbox_events` 和 `core.apply_project_rls`；未加入 manifest 前不能声称部署完成。
- 精确 Schema 绑定是单 winner；若历史数据存在相同 target 的多个“已发布”Schema，迁移后第一次建立 binding 需运营明确选择，不能自动选最新。
- 历史 annotation task 若没有可校验的 region lineage，迁移会保留 `region_code = NULL` 而 Repository 将其 fail-closed；BE24/运营只能根据真实历史关联补齐，不得从测试 seed 或默认 region 猜测回填。
- `core.audit_events` 中不保存 token、密码、签名 URL、对象 key、Manifest secret 或原始异常；仅保存 project/region/resource/request/workflow locator、稳定错误码和 hash。
